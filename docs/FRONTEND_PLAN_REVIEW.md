## Important changes

- **T1.4/T1.6: independent reference provenance.** The reference is a move-permutation implementation, not a solver: generate known scramble state independently, then use inverse of known scramble or a trusted verified sequence for fixture solution. Cite exact upstream reference/table version and license. Never write tables from memory or generate all goldens from the implementation under test. Cross-check with actual Python Kociemba in Phase 2. Keep 500 seeded sequences if cheap; there is no reason to implement an entire Kociemba solver in TypeScript now.
- **T1.9/T1.10: elapsed semantics.** Clamping every rAF delta to 100ms makes elapsed time a simulation clock, not real active wall time when visible frames stall. Explicitly choose playback/simulated elapsed versus wall time, name displayed metric honestly, reset reference timestamp on Pause/Resume/visibility change, test overshoot and long visible stalls. Hidden-tab pause must not advance steps.
- **T1.13/T1.18: orientation.** Architecture §7.2 requires persistent U/F/R reference colors while inspecting another face. Preserve a minimal always-visible orientation cue and target-center color/direction in Phase 1; defer dynamic camera redesign only. User's camera-off process relies on this. Manual browser checks should validate an asymmetric R/U/F, B/D sequence, not merely that the logical endpoint is solved.
- **T1.6, §5: readiness.** `visionReady && solverReady` is insufficient to authorize *real* capture when `detectorMode=fixture`; fixture readiness must be visibly separate and never enable unlabelled live capture. Phase 1 may only implement blocked Live/no transport and explicit demo. Define request id/cancellation behavior; WS hello/ack/ROI details continue in Phase 3.
- **Testing scope.** Use independent test suite names/commands; the current plan lists verification but does not consistently use Superpowers checkbox RED→GREEN→commit tasks. Convert executable tasks into checkboxes with test assertions and expected failures; do not force a failing test for pure mechanical relocation or baseline characterization. Provide a Phase 1 final report and honest browser status if the environment lacks a supported browser.
- **No unnecessary architecture churn.** Four Zustand stores, new adapter and six engine files are proposed, not requirements. Keep them only where responsibilities and testability justify them; do not create empty directories or introduce a second authoritative state. Retain the existing cube engine's verified behavior. One canonical FaceletState is required.
- **Cross-references:** S5/S7 and migration table refer to T0.4 for dependency scan; the actual task is T0.3. Fix. Add T0.3 to dependency gate/report. Ensure final verification documents actual selected package manager, commands, and actual installed versions rather than placeholders.
